# CourseOS

CourseOS помогает методисту собрать курс: определить, чему научатся слушатели, распределить темы и часы, подобрать задания и проверить, помещается ли обучение в расписание. План, материалы и история изменений собраны в одном месте.

В этом репозитории — фронтенд приложения. Его можно запустить локально и пройти весь сценарий на готовых примерах. По умолчанию включён деморежим: сервер и ключи API для знакомства не нужны.

## Что можно сделать

- **Собрать план курса.** Указать аудиторию, цель, длительность и ограничения, затем уточнить недостающие детали.
- **Связать обучение с результатом.** Посмотреть на карте, какие темы и задания помогают освоить каждый навык и как он проверяется.
- **Проверить нагрузку.** Найти расхождения в часах и расписании до утверждения плана.
- **Посмотреть материалы.** Открыть демонстрационные конспекты, тесты, практические задания, проект и содержание слайдов.
- **Внести согласованные правки.** Сначала увидеть, что затронет изменение, затем применить его и сравнить версии.
- **Скачать результат.** Получить читаемое описание курса в Markdown или полные данные выбранной версии в JSON.

Решение об утверждении программы принимает методист. Приложение показывает, на чём основаны предложения и что ещё нужно проверить.

## Как запустить

Понадобятся Node.js версии 22.12 или новее и npm. В терминале, из корня репозитория:

```sh
cd courseos/frontend
npm ci
npm run dev
```

Откройте [http://127.0.0.1:5173](http://127.0.0.1:5173). Чтобы остановить приложение, нажмите `Ctrl+C` в терминале.

Публичное демо собирается и раздаётся на `0.0.0.0:8000`:

```sh
cd courseos/frontend
npm ci
npm run build
npm start
```

## С чего начать

Для первого знакомства подойдёт пример **«Первые шаги в Python»** — курс на 16 часов для школьников без опыта программирования.

1. Выберите пример на главной странице. Посмотрите, как заполнены цель, аудитория и условия обучения, затем отправьте запрос.
2. Откройте план: проверьте результаты обучения, темы, задания и распределение часов.
3. В разделе **«Проверка и утверждение»** разберите замечания. В блоке **«Почему курс устроен так»** выберите раздел и решение: в карточке показаны объяснение и следующий шаг. Здесь же можно найти нужное пояснение и скачать Markdown ещё до утверждения.
4. Отметьте проверку и нажмите **«Утвердить программу»**. После этого перейдите к материалам курса.
5. Попробуйте **«Согласованные правки»**: опишите изменение, посмотрите его влияние и примените предложенный план. Если меняется основа программы, её нужно утвердить снова.
6. Сравните версии и откройте **«Выгрузки»** в материалах, чтобы скачать Markdown или JSON.

Есть и другие примеры: ИИ для учителей, анализ данных для сотрудников банков, кибербезопасность и DevOps. В примере с кибербезопасностью нужно уточнить неполный запрос. В DevOps заложен конфликт: 256 часов не помещаются в 8 недель при нагрузке до 4 часов в день. На нём удобно посмотреть, как приложение предлагает пересмотреть сроки или нагрузку.

## Как работает деморежим

Демо воспроизводит процесс работы с курсом на заранее заданной логике и примерах. Языковая модель не вызывается: параметры запроса, проверки и материалы формируются правилами приложения, а материалы остаются черновиками для проверки методистом.

### Параметры запроса и расписание

- Перед построением программы показывается редактируемая сводка параметров. Если текст примера изменён, параметры нужно сверить и подтвердить вручную; явные расхождения часов и недель блокируют отправку.
- Подтверждение календаря сохраняет заданный дневной лимит. Нехватка вместимости видна заранее, а изменение лимита оформляется отдельным решением и требует нового утверждения.
- Вместимость и расписание — разные проверки. В примере с Python расписание готово: восемь занятий по два часа по средам и субботам в течение четырёх недель. В остальных программах занятия назначаются в календаре вручную, иначе приложение показывает, что расписания нет.

### Замечания и исключения

- Принятое исключение хранит исходное замечание, причину и область действия — в версии, JSON и Markdown.
- Исключение не превращает непроверенное соответствие в пройденное и не отменяет арифметику часов или обязательные ограничения.
- После изменения структуры программы область исключения проверяется заново.

### Материалы

- Банковские практикумы используют связанные синтетические таблицы `clients` и `loans` с датами, сегментами и просрочкой. Условия и ожидаемые значения видны в материале.
- Предметные вопросы подготовлены для примеров с Python, банковской аналитикой, учителями и кибербезопасностью; для DevOps — предметные собеседования. Для произвольного курса тест нужно разработать самостоятельно.
- Из вопроса, задания или слайда открывается редактор полей: видны изменения и зависимости, сохранение создаёт новую версию. Ручные правки защищены от перезаписи; исправление ключа меняется и в JSON, и в Markdown. Изменение критериев оценивания или связей требует нового утверждения.
- Все материалы требуют предметной вычитки.

### Разделы программы и выгрузки

Во вкладке **«Разделы программы»** видны поля образца АЦР. Раздел с повторами текста или незаполненными полями считается незавершённым. Структурная полнота не подтверждает предметную или нормативную экспертизу.

Готовность JSON, DOCX, PPTX и LMS показывается отдельно для каждого формата. В демо доступны Markdown и JSON; выгрузки в DOCX, PPTX и LMS требуют серверной реализации и не засчитываются как готовые.

### Профессиональные стандарты

В сборку входит локальный каталог четырёх профстандартов:

| Код | Профстандарт |
| --- | --- |
| 01.001 | Педагог |
| 06.042 | Специалист по большим данным |
| 06.033 | Специалист по защите информации в автоматизированных системах |
| 06.026 | Системный администратор информационно-коммуникационных систем |

Полные тексты, редакции, ссылки на приказы Минтруда, источники, дата получения и SHA-256 хранятся в [`catalog.json`](courseos/frontend/src/entities/course/model/professional-standards/catalog.json). Тексты получены 15 октября 2026 года из открытых копий ГАРАНТ и Контур.Норматив; актуальность редакции и применимость проверяет методист. Серверная база не подключена: выбранный текст сохраняется вместе с курсом в браузере.

Чтобы сменить документ, нажмите в плане программы **«Изменить профстандарт»** и выберите стандарт из каталога, вставьте свой текст с названием и ссылкой или выберите **«Без профстандарта»**. Сохранение создаёт новую версию, сбрасывает связи результатов с прежним документом и требует повторного утверждения; прочие источники сохраняются.

Наличие текста профстандарта не означает, что программа покрывает всю квалификацию. В примерах с банковской аналитикой и DevOps стандарты используются только как кандидаты для части трудовых функций.

### Источники

В демо можно добавить текст источника и сохранить ссылку. Содержимое по ссылке не загружается, а извлечение текста из PDF и DOCX требует сервера.

### Хранение данных

Курсы, версии и решения сохраняются в браузере и остаются после перезагрузки страницы.

- Открывайте приложение по одному адресу: `localhost` и `127.0.0.1` используют разные хранилища.
- Перед очисткой данных браузера или нажатием **«Сбросить демоданные»** скачайте архив в блоке **«Хранилище и история»** на главной или во вкладке выгрузок. Архив включает все версии и невосстановленные данные.
- История не сокращается автоматически. После 15 версий приложение предлагает скачать архив и вручную удалить старые неутверждённые версии; утверждённые версии сохраняются всегда.
- Формат хранилища версионирован: совместимые данные прежнего формата мигрируют при открытии. Повреждённый курс изолируется, его исходные данные можно скачать, остальные курсы остаются доступны.
- Если квота браузера исчерпана, неудачная запись не затирает прежнее хранилище.

## Подключение сервера

Во фронтенде предусмотрен режим `live` для работы с внешним API. Сам сервер в репозиторий не входит.

Создайте файл `.env.local` в папке `courseos/frontend` по образцу `.env.example`:

```dotenv
VITE_COURSE_MODE=live
VITE_COURSE_API_URL=/api/v1
```

Укажите адрес своего API и перезапустите приложение. Режим также можно переключить в верхней панели; выбор сохраняется в браузере. Если сервер недоступен, приложение покажет ошибку подключения.

Сервер должен поддерживать [контракт фронтенда](courseos/frontend/src/entities/course/api/contract.ts) и авторизацию через cookie. Если он работает на другом адресе, потребуется настройка CORS. Ключи языковых моделей храните на сервере: переменные `VITE_*` доступны в браузере.

## Для разработки

Фронтенд написан на React и TypeScript, собирается через Vite. Для форм используются React Hook Form и Zod, для запросов — TanStack Query. Проверки написаны на Vitest и Playwright.

Основные папки внутри `courseos/frontend`:

| Папка | Что внутри |
| --- | --- |
| `src/app` | Оболочка приложения, навигация и общие стили |
| `src/pages` | Создание курса, план, карта результатов, материалы и сравнение версий |
| `src/entities` | Данные курса, правила проверок и работа с API |
| `src/features` | Загрузка источников, правки и выгрузки |
| `src/shared` | Общие компоненты, настройки и вспомогательные функции |
| `tests` | Проверки логики и сценариев в браузере |

Команды выполняются из папки `courseos/frontend`:

```sh
npm run typecheck  # Проверить типы TypeScript
npm run lint       # Проверить форматирование исходников и тестов
npm test           # Запустить тесты логики
npm run build      # Проверить типы и собрать приложение в dist
```

Для браузерных тестов сначала запустите `npm run dev` в отдельном терминале, затем:

```sh
npm run test:e2e
```

По умолчанию используется Google Chrome, установленный в стандартную папку приложений macOS. Для другого расположения браузера укажите путь:

```sh
COURSEOS_BROWSER=/path/to/chrome npm run test:e2e
```

Готовую сборку можно посмотреть локально:

```sh
npm run preview -- --port 4173
```

Для размещения на хостинге используйте содержимое `dist`. Настройте сервер так, чтобы при прямом открытии внутренних страниц он возвращал `index.html`.

### Размещение на Vercel

В настройках проекта укажите **Root Directory** — корень репозитория (оставьте поле пустым). Файл `vercel.json` в корне задаёт установку зависимостей и сборку из `courseos/frontend`, каталог результата `courseos/frontend/dist` и открытие внутренних страниц через `index.html`.

После изменения настроек или добавления конфигурации запустите новый deployment. Если адрес по-прежнему возвращает `404 NOT_FOUND`, проверьте, что нужный production deployment успешно завершён и домен привязан к этому проекту в разделе **Settings → Domains**.
